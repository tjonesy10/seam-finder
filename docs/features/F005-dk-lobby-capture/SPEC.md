## Problem / job to be done

Capture upcoming Classic prices automatically while they exist, without replacing Cosmo's official-export path or exposing raw salaries. The current lobby is not a historical archive. Keep each source snapshot and each capture attempt attributable for later private tooling.

## Requirements

- **R1** Add a bounded unauthenticated live-lobby CSV capture CLI and a new append-only private source table; never feed captures through F004's replacement loader.
- **R2** Automatically capture only the unique upcoming Sunday-afternoon NFL Classic draft group whose verified game set equals all REG games kicking off 1:00–4:30 PM America/New_York, including holiday weeks, with verified Classic rules. Do not substitute a Saturday, holiday, or other slate. Fail closed when the candidate is missing, ambiguous, non-Classic, or not an exact game-set match. A manual explicit id may target another multi-game REG Classic slate and must not be labeled Sunday main. Both paths require the independent authority/raw-source/receipt/current-PG chain below; internal row validity or a fresh games load cannot establish completeness.
- **R3** Use in-repo GitHub Actions at Cosmo's approved cadence plus manual dispatch: Wednesday 10:00 America/New_York during REG season only, DST-correct, no Sunday refresh. GitHub may delay or drop scheduled runs, and a public repository disables schedules after 60 days without activity. This docs package records the schedule and does not activate it. Off-season classification requires explicit finite calendar coverage and complete independently reviewed season evidence; observed endpoints, calendar months, or terminal-week presence are not completeness evidence.
- **R4** Preserve exact bounded raw bytes/rows, source metadata, independent attempt timestamps and content hashes; repeated identical bytes/identity/parser do not duplicate parsed rows. Retain the bounded raw nflverse schedule object, independently approved inventory/reference, full REG ID set/count, source version/publication/retrieval evidence and source-to-PG receipt used by each attempt; never reconstruct upstream evidence from PG rows.
- **R5** Retain the raw artifact, observation, and parseable ledger for invalid evidence. Publish a usable snapshot and its `dk_lobby_salaries` rows atomically only when every salary is valid and the other F005 validity rules pass. Any invalid salary rejects that usable snapshot. Failures leave previous good snapshots untouched. Every invocation that can reach the database has a sanitized load_runs audit. An unreachable database exits nonzero and does not claim a persisted audit row.
- **R6** Stop cleanly on denial/rate limit/challenge, use bounded transient retries/timeouts only, no credentials or bypass.
- **R7** Implement private-schema isolation and storage guards from the shared dictionary, including F004 web-grant hardening; no public salary API/page/download or raw logs/fixtures.
- **R8** Preserve F004 CLI/staged workflow and F003 data/attribution unchanged; no optimizer, mappings to fabricated players, or production rollout in this feature's planning package.
- **R9** Persist every capture attempt in private Neon with wall-clock `started_at` and `finished_at` plus monotonic `duration_ms`, for success, failure, skip, and repeated identical content. Link the attempt to its snapshot and source rows when they exist. Do not infer elapsed time by subtracting clocks, do not fabricate completion after a crash, and do not put secrets or raw bodies in public logs.

## User stories

- As Cosmo, I want prices captured regularly without manually exporting, so that private future tooling has contemporaneous evidence.
- As Cosmo, I want my staged official export kept separate, so that an unavailable unofficial endpoint does not remove my fallback.
- As a reviewer, I want each failed and repeated attempt recorded without mutating prior prices, so that I can reproduce source selection.

## Observable behavior

### Inputs and CLI contract (proposed for the later build)

`python -m loader.dk_lobby --season YYYY --week N [--draft-group-id ID | --selection sunday-afternoon] [--trigger local|manual|schedule]`

`--season/--week` identify a requested REG week, not a slate. Positive numeric draft-group ID is validated against live metadata and the requested week; no arbitrary request URL/path input. `--selection sunday-afternoon` is the approved automatic rule: the **unique** group whose verified games equal exactly all REG games kicking off on the upcoming Sunday from 1:00–4:30 PM America/New_York (inclusive), contest type 21, and verified Classic roster/rules. This includes holiday weeks. It is not "most games" or "most contests", and it does not switch to a Saturday or other holiday slate when that Sunday set is missing. A manual explicit ID may target another multi-game REG Classic slate with exact evidence; it must not be labeled Sunday main. No file upload/API/UI.

The approved cadence and Sunday slate rule are unchanged, and this docs package does not activate the schedule. Two qualifying groups are ambiguous unless explicitly reviewed equivalence evidence chooses one; no lowest-ID tie-break. Before any DK request, verify the full schedule-evidence chain below. A fully verified active season with no exact Sunday-afternoon set is `slate_unavailable`, not a substitute slate or off-season. Missing, uncertified, stale, or contradictory evidence is `schedule_evidence_missing`, exit 1, zero DK calls, and no usable salary snapshot. Only an independently supported finite interseason gap permits skipped/off_season. Missing Sunday rows, an April date, week 18 being present, or last year's observed endpoints never prove that gap.

### Independent schedule-completeness prerequisite

Contract: [ADR 0007](../../adr/0007-authoritative-schedule-completeness.md) and the [schedule proof dictionary](../../data-dictionary.md#f005-schedule-completeness-proof-adr-0007-accepted). Cosmo approved this contract directly on 2026-11-06 19:14 EST, and ADR 0007 is Accepted by the PR #20 merge. No product question remains. No actual season inventory is certified.

1. **Authority, not a self-hash.** A separately approved and pinned authority bundle contains an exact full REG game-id and matchup inventory independently checked by the designated operator against an actual complete published league schedule reference. Preserve reference bytes, URL, SHA, and publication, retrieval, and review evidence. A preparation tool may propose inventory, but it cannot set its own observed set as the authoritative expected IDs. The operator-approved SHA pins the authority root and all permitted child inventories and gap proofs. Reference authenticity is the operator's review of published league material. Completeness is equality of that reviewed inventory with the raw source and the current Postgres partition. A stored hash does not approve itself.
2. **Explicit season census and exceptions.** Use the independently documented season-specific original scheduled count and team appearances as secondary reconciliation. The 2026 league announcement says 272 scheduled games and 17 per team. That census is not an acquired exact-ID manifest and is not a rule for other seasons. No automatic modern-era 272, week-1/17/18 presence, or week-count rule. Preserve original scheduled identities and named cancellation or ID-change tombstones with evidence. The authority explicitly defines the expected current nflverse source representation. Unexpected source removal, addition, or substitution fails, even if the count is unchanged. Null scores do not mean cancellation. Inventory, cancellation, and coverage changes require a new reviewed revision. Identity-preserving kickoff changes use fresh timing receipts automatically when they stay inside reviewed constraints.
3. **Raw before projection.** The existing nflverse refresh, when the private schema and migration gates are enabled, retains the exact full upstream schedules object it already downloaded plus a private immutable source-season receipt. The receipt includes raw SHA, length, origin, media type, version, publication evidence, retrieved_at, season, full REG ID list and count, and canonical normalized projection SHA, bound to the successful games load_run and the pinned authority. The source and IDs are parsed from upstream bytes independently of Postgres. A verified receipt requires nonempty actual publisher-version evidence, never a self-hash presented as a publisher version. It must prove expected inventory equality before issuing a verified receipt. A syntactically valid truncated upstream body with a newly calculated SHA is not sufficient. No new automated NFL or ESPN feed and no extra DK request. Original loader upsert semantics and public tables remain unchanged.
4. **Check current Postgres too.** In one consistent database read, require a succeeded matching load_run and verified authority, raw, and receipt links, then compare the entire current relevant season REG partition to the certified source projection, including identity, teams, type, week, date, weekday, time, and nulls. Any interior game or week deletion, extra or substituted row, or kickoff alteration fails `schedule_evidence_missing` before fetching DK, even if the target Sunday remains plausible. No silent repair or bypass from raw during capture. The engineering freshness default is a real upstream retrieval within 24 hours and at most 5 minutes of future clock skew. The source publication timestamp is separate and is not fabricated. A fresh public success flag or a copied file mtime is not a retrieval receipt.
5. **Do not require all future kickoffs now.** Identity completeness can hold while later games are TBD. Any fixture that may fall on the target Sunday must have a resolved kickoff. An unresolved fixture may be excluded only with an independently evidenced possible-playing interval that is disjoint from that Sunday. A missing, unbounded, or contradictory interval, or a target-Sunday date with an unknown time, fails. Published future flex windows can be reviewed at initial onboarding. Do not guess seven-day or week-18 windows. A known future final-week TBD window that is disjoint from this Sunday must not block an otherwise valid earlier-week capture.
6. **Explicit off-season coverage.** Select the season through approved finite calendar coverage, not month arithmetic or whichever old rows remain. Compute conservative REG envelopes over all certified fixtures, using possible-playing intervals for unresolved times and explicit cancellations and postponements. A gap proof requires prior closure plus a verified next-season earliest bound or an independently published no-REG-through bound, with raw supporting evidence and an expiration. A prior completed season alone is not indefinite coverage. April with incomplete prior data fails. April without a supported gap also fails even if the prior rows are complete. A valid finite gap is a positive off-season success path. Valid in-season authority and receipts are the automatic capture path. This contract is not "always skip."
7. **Persist and fail safely.** Keep authority, raw, receipt, and verification outcome references privately on the attempt. Reused salary content gets a new observation pointing at the schedule proof actually used. Failed evidence checks retain bounded diagnostic artifacts and subreasons and the existing monotonic timing. Public audit stays codes and counts. No new salary snapshot and no rewrite of prior good salaries. Existing size guards apply. No external request is permitted merely to repair missing authority. The owner-designated operator may stage approved references separately. Migration and production staging still require explicit approval. No season inventory is certified by approving this text.

This adds a small opt-in provenance producer to the normal games refresh. Existing F001, F003, and F004 behavior when private gates are disabled remains unchanged. F005 cannot certify without a receipt. The full-season league authority is a declared operator trust boundary. It is neither an upstream completeness guarantee nor a claim of perfect correctness after retrieval.

### Validation and persistence

Use the shared dictionary for actual types/keys and evidence retention. F005 builds artifacts/observations/snapshots/source-row ledger and `dk_lobby_salaries` only. The dictionary's nullable salary column does not let F005 publish a usable snapshot. Required DK headers: Position, Name + ID, Name, ID, Roster Position, Salary, Game Info, TeamAbbrev; AvgPointsPerGame may be blank; BOM allowed, column order free, extra Status/unknown columns preserved. Parse exact bytes, keep ordered raw tokens. No inferred DK ID from name or draftables player_id. Duplicate DK IDs, contradictory rows, any invalid salary, missing names, missing team/game evidence, or mismatched metadata reject the usable snapshot. Raw artifact, observation, and parseable ledger remain; `dk_lobby_salaries` gets no rows for that capture. A null salary stored only in the ledger is not a valid captured salary. Distinct parsed games >1 and no CPT in any Roster Position required. Validate complete CSV game set against selected group, kickoffs, requested season/week and Classic rules. Unknown roster rule cannot be "verified" from merely seeing FLEX.

Source scope includes group ID and game/rule evidence, content SHA, parser version; fetched_at is an observation timestamp, not a dedupe key. Same content creates a new observation linking existing parsed snapshot. A→B→A must remain three observations and two content snapshots. Changed game/kickoff/rules evidence makes a different metadata revision even with same bytes. No delete/update of successful source rows. F008 will own identity/slate mappings, not this loader.

Durable raw/attempt transaction precedes validation, per-file normalized transaction publishes only complete valid snapshot, and audit finalization follows shared crash-recovery contract. Storage guard violation → failed reason, no snapshot, prior state intact; under-limit rejected CSV/body retained. Structural parse failure may have no row ledger but always has bounded artifact evidence. Failed DB connection exits nonzero; do not claim an audit row was persisted if DB could not be reached. Public load_runs contains only dataset/counts/reason codes, private observation contains detailed path/status evidence.

### Attempt timing

Each capture attempt, including success, fetch failure, validation failure, off-season skip, and repeated identical content, is one `salary_observations` row. `started_at` and `finished_at` are wall-clock `timestamptz` values. `duration_ms` is milliseconds measured with a monotonic timer between the start and the terminal write. It is never `finished_at - started_at` and never `load_runs.finished_at - load_runs.started_at`. Public `load_runs` may store compatible wall times and has no duration column. When a snapshot is published, or when repeated content reuses one, `snapshot_id` links the attempt to that snapshot and its source rows. A failed or skipped attempt that publishes no snapshot still stores timing and leaves `snapshot_id` null. Status plus a sanitized reason/error are stored privately. Public logs, workflow output, and `load_runs.notes`/`error` contain reason codes and counts only: no secrets, raw bodies, or salary rows. If the process crashes or is interrupted before the terminal timing write, `finished_at` and `duration_ms` stay null. Recovery must not invent them or mark that attempt completed. Reconcile a running attempt only with matching durable commit evidence; otherwise mark it interrupted/failed, leave the missing monotonic duration null, and start a new attempt. If the database cannot be reached, exit nonzero and do not claim a timing or audit row exists.
